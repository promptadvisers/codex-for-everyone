# Personal recurring-task project guidance

- Read PROJECT-README.md and course-guide/TASK-CARD.md before work. Use the selected task's audience, inputs, reporting rule and checks. Ask about missing material decisions.
- Use only the chosen input folder. Do not blend the three practice scenarios or import conventions from another project.
- Preserve source inputs and write new deliverables under output/.
- Cite factual claims with filenames and relevant date/section/row IDs. Separate supported facts from implications.
- Report missing, stale or conflicting evidence. Do not invent owners, dates, totals or approvals.
- Keep each skill focused on its selected task. Use a unique name and preserve existing installed skills.
- Test the method before scheduling. A saved schedule is not proof of execution. Record actual run evidence and review failures.
- Do not send/publish outputs merely because the skill ran.
