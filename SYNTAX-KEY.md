# Syntax key

## Names you will see

| Name | What it means here |
|---|---|
| Monday Brief | The weekly project update we prepare for the fictional VP |
| AGENTS.md | A text file holding working conventions for a project |
| Skill | Saved instructions and supporting files for repeating a kind of task |
| SKILL.md | The entry file containing a skill’s instructions |
| oreilly-monday-brief | The example skill name for the Northstar workflow |
| Northstar Update | A prepared fictional Drive document used in the instructor’s connection demo |
| Addendum | A separate note of supported changes and unresolved conflicts from that document |
| Checkpoint | A prepared recovery copy, not proof that your own task has run |
| Run log | A record of what happened during a task, including any errors |

- Plain language is the main interface. Goal / Context / Constraints / Done when is a useful format, not required syntax.
- /plan selects Plan mode. Inspect and agree on the plan; leave that mode before asking to save or implement it.
- $skill-creator asks for the skill-creation method. $your-verified-skill-name invokes your installed skill. Replace the example name with the one you verified.
- [bracketed fields] are placeholders. Replace them before sending; do not leave the brackets as your task description.
- .md is a readable text document. Open it in the app file preview. You do not need a coding editor.
- sources/ or output/ is a folder path relative to the project you opened. Keep the project name visible.
- WATCH means instructor demonstration. DO means act in your project. CHECK means inspect evidence before continuing.
- A source citation points to evidence. Read that evidence; a citation does not guarantee the sentence is true.
